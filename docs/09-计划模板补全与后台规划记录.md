### A4 图床现状澄清（**不是缺依赖**）

**现状**
- `services/storage.py` 已实现双后端：`local`（默认）/ `s3`（R2 / OSS 等 S3 兼容）。
- 当前 `storage_backend = "local"`：上传落 `api/static/...`，返回 `/static/{key}` 相对路径。
- `/static/exercises`、`/static/plans`、`/static/studio` 已在 `main.py` 挂载；H5 `vite.config.ts` 已代理 `/static` 到 8000。

**澄清**
- 上传后拿到本地地址，**不是因为没装依赖**。`boto3` 只有切到 `storage_backend=s3` 时才需要；local 模式不需要任何额外依赖。
- 真正没做的事是：**没有把后端从 local 切到对象存储**。

**待决策（暂不做）**
- 是否接 R2 / OSS。要上时只需：
  1. `pip install boto3`
  2. `.env` 配：`STORAGE_BACKEND=s3`、`S3_ENDPOINT_URL`、`S3_BUCKET_NAME`、`S3_PUBLIC_BASE_URL`、`S3_ACCESS_KEY_ID`、`S3_SECRET_ACCESS_KEY`
  3. 代码不用改。
- 注意：`/static/...` 相对路径只在 H5 与 API 同域下成立；将来封装 App / 小程序前，必须先切对象存储。

## B. 暂不实现，仅记录的后台规划（后面再细聊实现思路）

### B1 内容资产线
动作库 / 素材库 / 内容工坊 / 计划模板。工坊交互终版见 `docs/设计稿/内容工坊-交互重构/`。

### B2 AI 体验线
- **Badcase 池**：H5 用户反馈的对话坏案例，按归因分流（意图识别 / 工具调用 / 回答质量 / 长对话）。
- **评测台**：H5 的 AI 能力评测——评测集、跑批、规则分 + 裁判模型分、版本对比。**不是**动作数据打分。
- **设置**：LLM 配置、Prompt 版本管理。

### B3 Token / 成本监测
- 独立记 `llm_usage_log`（场景 / 模型 / 输入输出 tokens / 时间）；价格表单独一张 `llm_model_price`，价格不写死在代码里；按场景聚合成本。上线后再接。

### B4 前后端分层（不拆仓）
- 现状：接口都挂在 H5 项目里。后面补路由前缀 `/h5/*`、`/admin/*`，分层服务；共用一层服务，先不拆仓库。
- 隐患：`database_url = sqlite:///./data/gym.db` 是相对 CWD，启动目录不同会连错库；需改成基于 settings 的绝对路径。

### B5 分化类型设计约定
- 代码里**不要**把三 / 四 / 五分化做成枚举；只存 `days_per_week + 板块部位集合`，标签由 `_derive_scene_tag` 派生。后续新增分化不用改代码。
