## 1. 原始反馈（使用方原话复述）

> 这一段是使用后台内容工坊、上传一条话比较多的长视频后遇到的实际情况，便于评审者理解「为什么要改」。

1. **转写慢**：话多的长视频，字幕转写大约要二十分钟。慢本身可以接受（可以一次性挂多条批量跑），只要能实现就行，不是首要矛盾。
2. **没做的动作被抽进清单（假阳性）**：视频里人物话多，热身、闲聊中会提到动作名——比如「哪个部位不适，可以通过 XX 动作改善」，或其他问题里顺带提到 XX 动作。LLM 分析字幕时把这些口头提及的动作单独拎出来，当成了动作清单里的动作。一共十来个动作，有两三个实际是没做的。
3. **动作定位不准（串台）**：审核时要点回那一秒核对，发现视频根本不在讲这个动作。有时标签写的是「杠铃卧推」，点进去画面在讲热身；标签写「夹胸」，进去在讲杠铃卧推。也有一部分是正常的，进去讲的就是这个动作。
4. **审核耗精力**：动作不存在、定位又不准，只能一个个点回去看视频核对，很耗时间和精力。

**使用方的取向**：问题主要怀疑两处——① 提示词没把「不算正式动作」的情形限制住；② 选区向后延伸的认词规则不完善。同时明确提出一个约束：**规则尽量不要写死成一串口语词，否则下次出现别的说法，又要回来加词。**

## 2. 现状链路（代码事实）

后端：`api/app/services/studio_service.py`；目录子串命中：`api/app/exercises_catalog.py`；前端：`admin/src/pages/StudioPage.tsx`。

1. **下载**：ytdlp + cookie 拉视频。
2. **抽音轨**：ffmpeg 转 16k 单声道 wav。
3. **转写 `_transcribe`**：faster-whisper，默认 **CPU + int8 + small**，`beam_size=5 / best_of=5 / VAD`，`language=zh`，带中文领域词 `initial_prompt`；产出 `segments[]{start, end, text}`。
4. **LLM 拆课 `_llm_extract_plan`**：字幕按 **5 分钟一块、30 秒重叠**（`_chunk_segments`），逐块调 DeepSeek `complete_json`；抽取 prompt 为 `_STUDIO_PARSE_SYSTEM`；另把约 100 个库内动作名经 `_build_name_vocabulary` 作为对照词表喂给模型。跨块结果由 `_merge_llm_blocks` 按（部位, 归一化名）合并去重，保留条按 `_llm_item_teach_score`（要领数×100 + 组次×40 + 时间）择优。
5. **启发式兜底**（LLM 失败 / 返回空时）：`find_catalog_mentions_in_text` 对字幕做**纯子串命中**库内动作名，最多 12 条；或按「第 N 个动作 / 下一个动作」切文本。
6. **挂时间戳 `_row_from_item` → `_snippet_for_name`**：先取 LLM 给的 `spoken_at`，再拿动作名在全部字幕里子串重找一句；按邻近词加分（`_TEACH_HINTS` 教学词 +12 / `_INTRO_HINTS` 开场词 −8 / 顿号罗列句 −4）取最高分句；选区向后延伸 ≤8 秒（`_SNIPPET_MAX_SEC`），遇 `_NEXT_ACTION` 正则（第 N 个动作 / 下一个动作 / 收尾 / 首先先做）才断。`_keep_snippets_on_own_action` 保证选区不早于本动作开口、不盖住下一条开口。
7. **匹配库动作**：`exercise_match` 百分制打分 → 候选 / 灯色。
8. **前端审核台**：`anchorOf` 取 `spoken_at`，点卡片 `focusWaveAt(snippet)` → `seekTo(start)` 跳视频；卡片灯色 `trafficOf` 只表达绑定状态（绿=已绑 / 黄=有候选 / 红=库外）。

## 3. 问题归因

### 3.1 假阳性：提及被当成正式动作（新增，现有工单未覆盖）

- **Prompt 排除条件是场景罗列，不是角色判定**：现规则只写「跳过寒暄闲聊」「片头报菜名单独不抽」，没覆盖反馈里的几类——热身闲聊、举例/建议（「不适可以靠 XX 改善」）、回顾上一个动作、对比旧动作。模型看到动作名即倾向抽出。
- **对照词表反诱导**：抽取阶段把库内动作名喂给模型，强化了「听到这些词就拎出来」。
- **兜底是纯子串匹配，不看语境**：`find_catalog_mentions_in_text` 只要字幕出现库名就算一条；LLM 返回不完整时，兜底必然产出假动作。
- **缺证据校验**：抽出的动作不要求附带「是哪句话、以什么角色引出的」；后端也没有二次过滤——附近没有组次 / 要领 / 做组线索的条目照样进主清单。草稿行结构里目前没有 evidence（支撑原话 + 句时间戳）字段。

### 3.2 串台错位：锚点挂到相邻动作的句子（新增；与 13 P1-2 的「偏早」不同）

> 13 P1-2 解决的是**同一动作早 1～3 秒**（介绍句 vs 首 rep）；本节是**锚点错挂到别的动作句子上**，两者互补。

- **子串重找无条件覆盖 LLM 时间戳（首要代码缺陷）**：`_row_from_item` 在取得 LLM 给出的 `spoken_at` 后，先经 `repair_spoken_name` 改写为 `spoken`，再无条件调用 `_snippet_for_name(segments, spoken)` 扫全片字幕并**直接覆盖** `spoken_at`（即便 LLM 本来定位准确也会被拉偏）。且 `_build_name_vocabulary` 诱导 LLM 将口语改成库内标准名后，标准名在原字幕里常搜不到或误中其他段落。
- **Whisper 句边界跨动作**：VAD 合并出的一句话本身可能跨两个动作，`start` 落在上一动作尾部，下一条随之错位。
- **重叠区偏置末尾 + 全片覆盖合并**：`_llm_item_teach_score` 含 `+ at`（秒数越靠后分越高），导致视频后半段的回顾/总结复述比前面正式教学分更高，合并时覆盖正确时间戳；同时 `_merge_llm_blocks` 跨全片按 `(muscle, canonicalize_exercise(spoken))` 去重，热身与正片同名动作也会互相覆盖。
- **断句词表太窄**：选区结束只认 `_NEXT_ACTION` 那几个正则说法；教练说「我们来做…」「换一个」等不在表内，选区会盖进下一动作开头。

### 3.3 转写慢（可接受，排最后）

CPU 跑 small + `beam_size=5 / best_of=5`，解码开销大；整段串行（抽音轨 → 加载模型 → 全量转写 → 逐块 LLM）。模型已进程内复用，冷启动除外。

### 3.4 审核低效（产品层）

- 卡片只有动作名 + 绑定灯色，**不显示支撑原话与时间戳**，不跳视频无法初判「到底做没做」。
- 无可疑项前置：假阳性、低置信、锚点串台的条目不会被聚到一起优先审。
- 锚点不准时只能手动拖选区，没有按相邻字幕句微调；缺少批量删除 / 批量绑定。

## 4. 设计原则：语义判断交 LLM，后端只做结构校验

**核心取向（回应使用方「不要写死一串口语词」的约束）：**

> 后端规则只管格式、顺序、时长、时间戳合不合理；「这句话算不算正式动作、是举例还是教学、在哪一句话开始」这类**开放口语语义判断，由 LLM 按角色输出结构化结论，后端承接结果，不再维护中文口语连接词枚举。**

### 4.1 哪些可以写死（封闭、稳定、与说法无关）

- 选区时长上限 / 最小区段、时间戳单调不回退、组次数值格式；
- `role`（main / assist / isolation / warmup）、部位等封闭枚举；
- 库内动作名匹配、同音纠错（库里有什么是有限词表）；
- 转写领域名词（whisper `initial_prompt` 里的动作名词，帮模型听清动作名，可留）。

### 4.2 哪些不该写死（开放口语语义，归 LLM）

- 教学词 / 开场词 / 换动作词 / 罗列句式等中文口语表达；
- 现状代码里的 `_TEACH_HINTS`、`_INTRO_HINTS`、`_NEXT_ACTION` 即属此类，是「下次出现新说法又要补」的源头，方案中收窄或移除。

### 4.3 兜底不靠补词表，靠标可疑交人工

LLM 也会判错。后端防线应是**与说法无关**的：evidence 缺失、时间戳越界、两条选区重叠 → 标可疑，进审核台优先看；而不是再加一个关键词正则去拦。人工删除 / 改绑的条目沉淀为样本（衔接 `14` AI-Ops 未命中池），定期看误判集中在哪类场景；真要补，也是在 prompt 里补一个**反例场景类型**，不是补一串具体词。

## 5. 改造方案（分优先级，按 P0 → P1 → P2 实施）

### P0 · 压假阳性（最省审核时间）

**方案**

1. **Prompt 角色化输出**：每条动作带结构化字段——
   - `scene`：`teaching`（正式教学 / 做组）/ `warmup`（热身激活）/ `example`（举例假设、改善建议）/ `recall`（回顾对比旧动作）/ `intro`（开场罗列）；
   - LLM 回 `evidence_seg`（全局字幕句序号，见 P1）与 `evidence_text`（支撑该动作的原话原句）；后端落草稿行时结构化为嵌套对象 `evidence: { seg_index, text, start, end }`（`seg_index` 即 `evidence_seg`）；
   - `role`、组次、要领沿现状。
   - 判定规则给**场景类型与标准**，不给禁用词清单：`example / recall / intro` 不进主清单；**`warmup` 映射为 `role="warmup"` 保留在热身区且不填假组次**（不与未做动作混删）；无支撑句不抽。
2. **后端结构校验**：除热身外，动作附近窗口内无任何组次 / 要领 / 做组线索，或缺 evidence 的条目，标 `suspect=true`（并记录 `suspect_reason`），不直接按正常主项对待；**`scene/role=warmup` 不因缺组次被标可疑**。LLM 块级解析失败退回 `find_catalog_mentions_in_text` 启发式兜底时，必须过语境校验且整批标 `suspect=true`。
3. **对照词表移出抽取 prompt**：不再调用 `_build_name_vocabulary` 随抽取请求喂给 LLM；库名词表只保留在匹配阶段（`exercise_match`）使用。

**涉及**：`_STUDIO_PARSE_SYSTEM`、`_llm_extract_plan`（移除 `vocab` 注入）、`_parse_and_score` / `_row_from_item`（`scene` / `suspect` 标记）、`find_catalog_mentions_in_text` 兜底语境过滤与可疑标、草稿行结构补 `evidence` 字段。

**验收方向**

- 举例 / 建议 / 回顾 / 罗列类提及不再进主清单；热身保留为 `role="warmup"` 且不补假组次；
- 每条主清单动作可回溯到一句原话及时间戳；
- 同样字幕下，假阳性条数明显下降；兜底路径不再无标注混入正常清单。

### P1 · 修串台错位

**方案**

1. **喂给 LLM 全局序号字幕 `[#idx mm:ss]`，直取 `evidence_seg`**：
   - 改造 `_format_segment_lines`：在分块前保留每个 segment 在完整 `segments` 列表中的全局下标，格式化为 `[#42 03:15] 字幕内容`；
   - Prompt 要求每条动作输出 `evidence_seg`（整数下标）与 `evidence_text`；
   - `_row_from_item` **直接按 `segments[evidence_seg]` 取 `start / end` 与 `spoken_at`**，**禁止再调用 `_snippet_for_name` 全片重扫去覆盖 LLM 锚点**（`_snippet_for_name` 仅作 `evidence_seg` 缺失或越界时的降级兜底）。
2. **修复合并覆盖与末尾偏置**：
   - 去掉 `_llm_item_teach_score` 里的 `+ at`（时间越晚分越高）偏置，择优只看 `scene == "teaching"` 及要领/组次线索完整度；
   - `_merge_llm_blocks` 仅在**分块重叠窗口内（如两条 `spoken_at` 间隔 ≤ 45 秒）**合并同动作，不跨整条视频按 `(muscle, name)` 互相覆盖（允许热身与正式段、或不同时段重复出现同一动作）。
3. **边界用下一条 `evidence` 起点**：上一条选区结束锚到下一条 `evidence` 句起点，不再依赖「下一个动作」类换动作正则；保留 8 秒时长上限（`_SNIPPET_MAX_SEC`）作结构兜底。
4. **错位自检**：两条动作选区重叠超阈值、或时间戳回退，标记 `suspect=true`（`suspect_reason="overlap_or_out_of_order"`）待修；与 `13` P1-2 的 `rep_start` 互补落地。

**涉及**：`_format_segment_lines`、`_chunk_segments`（传递全局索引）、`_row_from_item`、`_snippet_for_name`（退为兜底）、`_keep_snippets_on_own_action`、`_merge_llm_blocks` / `_llm_item_teach_score`、前端锚点取值口径。

**验收方向**

- 点动作行，画面落在该动作正式教学段，不串到相邻动作或结尾回顾段；
- 串台/重叠条目可被自检标出；旧草稿无 `evidence` / `rep_start` 时回退不报错。

### P2 · 审核效率

**方案**

1. **卡片展示支撑原话一句 + 时间戳**：不跳视频即可初判；可疑项（`suspect=true`，含无证据 / 启发式兜底 / 重叠错位）置顶或支持一键筛选。
2. **字幕句锚点微调**：选区两端挂相邻字幕句，可按上一句 / 下一句锚点挪边界。
3. **批量操作**：清单多选删除、批量绑 top1；人工纠正条目回流样本池（接 `14` AI Ops 未命中池）。

**边界**：不改 `12` 已定的「卡片只绑定、要领写库在抽屉」；卡片新增的是只读证据展示与可疑角标，不往卡片里加要领控件。

### P3 · 转写性能（本期暂不做）

- 维持 `faster-whisper small + beam_size=5` 保障中文健身动作词识别率；不降级 `base` 以免增加人工审校成本。后续如有需要再单独评估 VAD 并行切片。

## 6. 落地前的排查回放步骤（先拿样本，别急着改）

1. **落中间产物**：取那条问题任务，导出 `transcript_json.segments`（每句 start/end/text）与 `draft_json`（每条动作名 / `spoken_at` / `snippet` / 要领 `source_at` / 候选 / 分数 / role / `parse_engine`）。先判定走的是 LLM 还是启发式兜底。
2. **逐条标注错因**：没做（假阳性）/ 做了但时间戳串台 / 匹配错名。
3. **分环节验假设**：
   - 转写层：错位边界那几句，whisper 的 start/end 是否本身跨动作；
   - LLM 层：错动作在原句里的角色（举例 / 热身 / 回顾 / 正式），词表是否诱导；
   - 对齐层：对比 LLM 原始 `spoken_at` 与 `_snippet_for_name` 命中句，定位是谁带偏时间戳；
   - 合并层：重叠区是否重复抽取、保留条是否分高但时间错。

## 8. 评审定稿口径（已拍板，按此执行）

1. **`evidence` 存放位置与兼容**：直接挂在每条草稿动作行 JSON 内，嵌套对象 `evidence: { seg_index, text, start, end }`，另带 `scene`、`suspect`、`suspect_reason`（LLM 侧输入契约里的 `evidence_seg` 即 `seg_index`）；旧草稿无字段时前端/后端默认回退 `spoken_at` 且不报错。
2. **`suspect` 与 `12 §3.1` 灯色关系**：**完全独立**。红 / 黄 / 绿灯只表达「SKU 绑定与发布状态」；`suspect` 作为独立警告角标（如「⚠ 疑似闲聊提及 / ⚠ 启发式兜底 / ⚠ 选区重叠」），前端支持置顶与筛选「只看可疑」。
3. **LLM 失败或 JSON 不合法兜底**：该分块降级为启发式抽词，但产出条目**全部标 `suspect=true`（`suspect_reason="fallback_heuristic"`）**交审核人一眼确认，不静默混入正常主清单。
4. **转写模型与参数**：本期维持 `small + beam_size=5` 不动（保证听清中文动作词，不做 P3 降级）。
5. **画面帧视觉校验**：本期不做，先由 `[#idx mm:ss]` + `evidence_seg` 解决串台问题。
