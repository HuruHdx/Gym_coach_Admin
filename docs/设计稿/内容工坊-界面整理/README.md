# 内容工坊 · 界面整理（诊断 + 改造方案）

> 2026-11-19。两张效果图 + 这篇说明，配合 `docs/09-计划模板补全与后台规划记录.md` 一起看。

---

## 一、为什么你觉得乱

不是审美问题，是**功能没有归属**。看代码就知道：

| 文件 | 大小 | 问题 |
|---|---|---|
| `src/pages/StudioPage.tsx` | 95.8 KB / 2400+ 行 | 所有功能塞在一个页面 |
| `src/pages/StudioPage.css` | 34.7 KB | 所有样式塞在一个文件 |

具体表现：

1. **一屏混了四类东西**：任务队列（列表）、视频操作（提取）、动作清单（数据编辑）、配置（Cookie / LLM）。
2. **右栏标题里塞了工具栏**（`renderRightTools` 放在 `col-head` 里）——工具没有归属，用户不知道这按钮管什么。
3. **详情是第二套三栏布局**（`detail-list / detail-main / detail-demo`），点进去整个空间关系变了，出来又变回去。
4. **按钮全是同级**：主操作、次操作、危险操作长得一样，没有主次。
5. **新功能只能挤**：GIF、封面、要点、字幕，实现时找不到位置，就往中栏和右栏里塞。

结果是：**"哪里能点"和"哪里是配置"没有视觉区分**。

## 二、三条改造原则

### 原则 1：配置就地出现，不建集中设置页

**结论：不单独做"设置页"。** 配置放在**它被需要的那一刻**：

| 配置 | 放哪 | 为什么 |
|---|---|---|
| Cookie / 读哪个浏览器 | **新建任务弹窗**，链接下面 | 有时效、分平台，失效时你正在建任务 |
| 处理程度（标准 / 只转字幕 / 连素材） | 新建任务弹窗 | 是按这条视频定的，不是全局默认 |
| GIF 尺寸 / 封面比例 | 点「导 GIF」「设封面」时弹参数小面板 | 只作用于这一次操作 |
| 模型 / Prompt | **服务端 `config.py` + env**，不进界面 | 改一次要重启，做成 UI 反而要维护版本和权限 |
| 存储后端 / CDN 前缀 | **服务端 env**，界面最多显示一行只读状态 | 要装 boto3、填密钥、重启服务，表单做不完 |

判断标准一句话：**会影响所有任务、而且几乎不变的，写进服务端配置；有时效或按次定的，就地出现。**

好处：没有"设置页里有一条我没配"，也就没有"Cookie 过期了还得专门跑一趟设置"。常态是零操作，失效时才冒一次提示。

### 原则 2：一个面板只干一件事，用职责标标出来

面板标题右侧加一个标签，让用户一眼知道这块是干嘛的：

| 标 | 含义 | 长什么样 |
|---|---|---|
| `只读` | 只能看，不能改 | 蓝灰，`#8fa0e8` |
| `操作区` | 能改数据 / 能框区间 | 主题绿 |
| `产出` | 会生成新文件 | 琥珀 |

这一条能直接干掉"不知道哪里竟然还能点"。

### 原则 3：全屏只有一个实心主按钮

- **主操作**：`发布`（每个视图只有一个，实心主题色）
- **次操作**：描边，行内出现（`播这段 / 设封面 / 导 GIF / 出库示范`）
- **危险操作**：红色，只在真要删的时候出现
- **不可点的东西**：不许有 hover 态、不许有边框按钮样式

## 三、两张图

### `01-工作台-重构后.png`

改了什么：

1. **三栏职责固定**：左=只读队列、中=操作区（视频+时间轴）、右=操作区（动作清单）。
2. **素材只有一个出口**：中栏的**选区操作条**。`播这段 / 设封面 / 导 GIF / 出库示范` 只在这里出现，别处不重复。
3. **"本次产出"有地方看了**：选区产出的 GIF / 封面 / 示范段，落在这个条里，能删、能出库。
4. **动作详情不再跳页**：点某一行，右栏底部滑出「动作卡」（绑定候选、要领、易错、节奏、两个出口），空间关系不变。
5. **动作卡的两个出口**：`仅存本次` / `写入动作库`——这才是把开源垃圾动作库替换成高质量库的入口。
6. 底部状态写人话：`2 个待绑定 · 1 个库外 / 修完才能发布`。

### `02-新建任务-Cookie就地配置.png`

这张替代了最初的"设置页"。三件事都塞进新建任务弹窗：

1. **平台自动识别**：贴完链接直接认出 `B站 · BV1xx411c7mD`，不用你选平台。
2. **Cookie 就地管**：链接下面一行 `Cookie 未配 · 720P 可用` + `从浏览器读取`。过期了就在这里点一下，不用去别处。
3. **处理程度按这条视频算**：`标准 / 只转字幕 / 连素材一起`，选完记住上次，不用每次重选。
4. **环境缺失前置拦住**：底部一行 `✓ yt-dlp ✓ faster-whisper ⚠ ffmpeg 未装`。缺什么在建任务时就知道，不是等跑到一半才失败。

> 之前那版「设置页」直接废弃。理由见原则 1：Cookie 有时效、按平台，模型和存储在 env 里，没有一样值得一个独立页面。

## 五、B站下载失败：真正的原因（不是 Cookie）

### 5.1 根因

`api/app/services/studio_service.py` 的 `_download_url()` 里，Referer **写死成抖音**：

```python
"--referer",
"https://www.douyin.com/",
```

B站对 `playurl` 接口做 Referer 校验（防盗链）。带着 `douyin.com` 的 Referer 去请求 B站 → **403**。

然后错误被归类成这句：

```python
if "fresh cookies" in low or "http error 403" in low or "403: forbidden" in low:
    return "平台拒绝访问（需要新鲜 Cookie）。"
```

所以你看到的是"没 Cookie"，实际是**请求头不对**。这条错误归类把 90% 的 B站失败都误导成 Cookie 问题。

### 5.2 修法（三行逻辑）

1. **Referer 按域名给**：
   - `douyin.com` → `https://www.douyin.com/`
   - `bilibili.com` / `b23.tv` → `https://www.bilibili.com/`
   - `youtube.com` → 不传
2. **先不带 Cookie 试一次**。B站公开视频**不需要登录**，能直接拿 480P / 720P。只有 1080P+、大会员、部分受限视频才要登录态。
3. **失败后再带 Cookie 重试**，而不是一开始就要求 Cookie。

### 5.3 关于"浏览器里 Cookie 是乱码"

不是加密，是两件事叠在一起：

- B站 Cookie 是一长串字段（`buvid3` / `buvid4` / `b_nut` / `_uuid` / `bili_jct` / `SESSDATA` / `buvid_fp` …），其中 `buvid3`、`buvid4` 本身就是很长的编码串。
- `SESSDATA` 是 **URL-encoded** 的，里面带 `%2C`（逗号），看着像乱码。

**你只需要 `SESSDATA`**（可选再带 `bili_jct`）。真要用 Cookie，别手抄：

- 优先：设置页选「从本机浏览器读」→ `--cookies-from-browser edge`（要**完全退出浏览器**，不然读不到库）
- 次选：装扩展 `Get cookies.txt LOCALLY` 导出 `cookies.txt`
- 兜底：不配 Cookie，直接下 720P

### 5.4 本机环境提醒

这台公司机的 venv 里**没装 `yt-dlp`**，PATH 里也**没有 `ffmpeg`**：

```
python -m yt_dlp --version  →  No module named yt_dlp
ffmpeg                       →  PATH 里没有
```

所以链接下载在这台机器上必然报「未安装 yt-dlp」。要测这条链路，回家那台（装过的）上测，或者先：

```
pip install yt-dlp
```

`ffmpeg` 是合并音视频必须的（B站 DASH 分离流），装完要**重启 API 进程**，否则 `shutil.which` 还是拿不到。

## 六、建议的改法顺序（不要一次重构）

1. **先修 Referer + 错误归类**（后端，10 行内，回家就能验）。这一步不通，工坊没有输入。
2. **删掉设置弹窗，Cookie 搬到新建任务弹窗**（配置从主界面消失，体感立刻变清楚）。
3. **动作详情改成右栏内嵌卡**（去掉第二套三栏布局）。
4. **合并中栏操作为选区操作条**（去掉重复按钮）。
5. 最后再谈视觉细节。

第 1、2 步做完，"乱"的感觉会掉一半。第 2 步的关键不是"多做一页设置"，而是**把设置这一层直接去掉**。
