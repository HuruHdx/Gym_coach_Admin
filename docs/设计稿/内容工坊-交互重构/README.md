## 二、不能理解错的 8 条规则

1. **字幕是证据层，不是主界面。**
   字幕默认收在「原文抽屉」里，只在核对时展开；不要做成常驻字幕列表铺在中栏。

2. **两条轨要分开画。**
   上轨 =「动作锚点」（LLM 抽取，带动作名 + 组次）；下轨 =「字幕分段」（whisper 原话）。
   数据来源不同，别合并成一条。

3. **`≈` 表示"他讲到这句的秒"，不是"动作开始的秒"。**
   所以锚点上的时间一律加 `≈`，且**不能**直接拿来切素材——切素材靠人拖波形。

4. **切片时长任意，默认不生成。**
   没有"固定 5 秒"这回事；只有选区操作条上的 `出库一段`，长度由选区决定（3~15s 甚至更长）。

5. **动作清单两个维度都要标。**
   行首圆点 = 动作绑定（绿=可信 / 黄=候选 / 红=库外）；
   行尾 tag = 素材状态（已切 ✓ / 用库里 / 库外待建）。
   两者不是一回事，别只留一个。

6. **绿灯折叠，不占视线。**
   全部可信的动作折叠成一行 `✓ 已自动通过 N 个`，右栏只列黄点和红点。

7. **发布门禁看红黄点。**
   还有黄/红点时主按钮是 `绑定 N 个 → 发布`；全绿才变成 `发布`。

8. **一条失败不阻塞队列。**
   抓取失败的任务转成「需补传」状态继续留在队列里，后面的任务照常跑。

## 三、视觉约定

- 深色主题（forge）：底 `#0d0f0e`、卡面 `#171b18`、分割线 `#2a312b`、强调色 `#c7f36b`
- 三个语义色：绿 `#63d69b`、黄 `#f0b35a`、红 `#ff7d73`
- 主按钮用强调色实心，次按钮描边，禁用态 40% 透明度
- 顶栏只放 `＋ 新建任务` 和 `⚙ 设置`；**模式选择、Cookie 都不要挂顶栏**

## 四、后端要配套改的地方（实现前先确认）

| 位置 | 现状 | 要改成 |
|---|---|---|
| `studio_service._parse_and_score` | 纯正则 + 子串匹配，无 LLM | 调用一次 LLM，输出动作/组次/热身/提示/锚点时间/置信度 |
| `_download_url` | `subprocess.run` 一把抓，无进度 | `Popen` 逐行读 `[download] xx%`，写百分比/速度/ETA/阶段 |
| 超时策略 | 固定 `timeout=120` | 改成「连续 30 秒无新进度」才判失败 |
| 失败原因 | 原始报错直接抛 | 归类成 403/无格式/作者关闭/网络中断，给对应按钮 |
| 失败处理 | 整条 pipeline 中断 | 标成 `需补传`，不阻塞队列 |
| 切片 | `_snippet_for_name` 固定 ±2.5s | 接受任意 `start/end`，默认不生成 |
| 素材获取 | 只有链接抓取 | 增加「直链」和「本地文件」两种入口 |

## 五、先不做（避免 Cursor 自行扩展）

- 不做多轨合成、字幕压制、加 BGM、导出成片（这是素材提取器，不是剪辑软件）
- 不做自动生成切片（必须人确认选区）
- 不把 H5 用户上传的训练视频接进这个工坊（那是另一条业务线，独立表、独立目录）
- 不在这一步接 VLM 看画面（画面区间由人拖，AI 只负责文字理解）
