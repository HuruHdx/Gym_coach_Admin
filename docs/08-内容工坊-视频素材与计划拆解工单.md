# 08 · 内容工坊：视频素材加工 + 计划拆解工单

> 上游：`01-总体架构与功能方案.md`、`05-分阶段实施路线图.md`（A4）、`07-计划模板后台配置台.md`。
> 本工单把原 A4「高光切片台」升级为统一的**内容工坊**，并新增「计划拆解」产物线。
> 重心仍在训练出计划；营养只留扩展口子，本期不写营养逻辑。

---

## 1. 背景与目标

### 1.1 现状

- 现有 A4 只规划了「单动作教学 MP4 → 字幕 → 高光切片 → 挂动作 `highlight_video`」一条线，尚未开工。
- 计划模板（`plan_templates → plan_blocks → plan_exercises`）已支持手工编排，但动作行需要运营逐条去抖音看视频、手抄动作与组次，成本高。
- 动作库部分 `name_zh` 为英译生僻名，口语叫法命中率低，需要在素材加工过程中反向反哺别名与命名。

### 1.2 要解决的三件事

1. **动作素材生产**：本地视频 / 链接 → 切片、GIF、封面、Cues/Mistakes，挂到动作 SKU 槽位（原 A4）。
2. **计划半自动拆解**：博主（如谭成义、凯圣王）训练视频 → 分段、抽动作行、匹配套库、打分 → 生成**模板草稿**，人工审核后发布。
3. **底层能力公共化**：转码、抽帧、字幕识别、高光定位、切片、GIF、打分抽成共用服务，两条产物线复用；老 `exercise_media` 表本期不重构。

### 1.3 本期不做

- C 端用户训练视频动作分析（姿态/角度纠错）：单独立项，本期只在素材层预留 `domain` 口子。
- 营养问答、食物热量库、搭配餐食、碳循环方案：仅留数据扩展位，不实现功能。
- 站内自动抓取作为正式主路径：链接解析为可选降级能力，抓不到就走本地上传。

## 2. 产品定位与命名

### 2.1 模块命名

- 一级导航由原「高光切片台 `/video-studio`」更名为 **「内容工坊」**，路由建议 `/studio`（旧 `/video-studio` 保留重定向）。
- 命名理由：产物不止切片，还包括 GIF、封面、计划拆解草稿；「高光切片」语义过窄。

### 2.2 页面结构：一个模块，两个产物标签页

```
内容工坊 /studio
├── 入库区（共用）：本地上传 + 粘贴链接尝试解析（失败转手动上传）
├── 标签页 ① 动作素材（原 A4）
│     视频/时间轴/字幕联动 → 选区切片 → 导出 GIF/封面 → 绑定动作 SKU 槽位 + 勾选 Cues/Mistakes
├── 标签页 ② 计划拆解（新增）
│     分段（热身/正式/收尾）→ 动作行草稿 → 匹配库/待绑定 → 打分分流 → 生成模板草稿
└── 共用：任务队列、字幕稿、抽帧候选、待绑定池、打分结果
```

**合并原则：流程共用，产物分流。**

| 层 | 归属 | 说明 |
|---|---|---|
| 入库 / 转码 / 抽帧 / Whisper 字幕 / 高光定位 / 切片 / GIF / 封面 | 共用服务 | 不写死动作或模板业务 |
| 待绑定池 | 共用 | 口语动作名连不上 SKU 统一进池，人工换绑 |
| 右侧审核面板 / 绑定对象 | 按标签页分流 | 动作素材绑 SKU 槽位；计划拆解绑模板板块/动作行 |
| 产物落库 | 分流 | 动作素材 → `exercise_media`；拆解 → `plan_templates` 草稿 |

### 2.3 与「媒体池 `/media-pool`」的边界

- **媒体池**：已入库/批量素材的看管与归属（A3，图片/GIF/视频文件绑定）。
- **内容工坊**：从原始视频出发的加工生产（字幕、切片、GIF、拆解草稿）。
- 两者通过待绑定池衔接：工坊产出的未匹配条目可进入媒体池统一绑定。

## 3. 两条产物线流程

### 3.1 标签页① · 动作素材（原 A4 闭环）

```
入库视频（本地/链接）
 → 转码压缩、抽帧、Faster-Whisper 时间戳字幕
 → LLM 推荐 15～45s 高光区间 + 提炼 Cues/Mistakes 草稿
 → 人工在时间轴微调选区，字幕/播放头/选区联动
 → 导出：带声 MP4（highlight_video）/ 循环 GIF（demo_gif）/ 封面帧
 → 确认绑定动作 SKU + 槽位，勾选入库的 Cues/Mistakes
 → 写 exercise_media(status=draft)，发布后旧版归档（沿用 A2 发布/回滚机制）
```

### 3.2 标签页② · 计划拆解（新增）

```
入库视频（本地/链接；可只讲一个部位，如胸肩）
 → 共用管线：转码 / 抽帧 / 字幕 / 视觉候选动作
 → LLM 分段：热身段 / 正式训练段 / 收尾段
 → 每段抽取动作行：口语动作名、角色、组次(有则记)、时间戳片段、来源标记
 → 匹配动作库：高置信自动挂 SKU；低置信进待绑定池；库内无对应动作先留自由文本行
 → 四维打分 → 绿/红分流
 → 生成 PlanTemplate 草稿（is_published=false，template_type 多为 fixed）
 → 人工审核：待绑定换绑、补组次、调顺序、挂片段/GIF、反哺别名
 → 确认后发布进 H5
```

**单段视频只出一个板块（block）**；同一博主多条视频，后台手动拼成一个多分化模板。不强求一次拆出整套计划。

## 4. 关键业务规则

### 4.1 热身段处理

博主开场讲的热身与正式动作分开存，不混进正式动作行：

| 视频段落 | 落地方式 | 字段口径 |
|---|---|---|
| 热身动作（肩绕环、弹力带拉开、空杆递增等） | 动作行，`role=warmup` | 复用现有 `PLAN_SLOT_ROLES` 的 `warmup`；只记 `warmup_sets`/次数，不参与 1RM、不计正式组容量（对齐 `TrainingSetLog.is_warmup`） |
| 热身流程/口头说明（活动关节、递增方式） | 不落动作行 | 存入 `PlanBlock.note` 或模板 `description`，作为板块热身备注 |
| 收尾拉伸/冷身 | 可选，存板块 `note` | 不进正式组 |

- LLM 先按「热身段 / 正式段 / 收尾段」切分，再抽动作行。
- 博主未讲热身则留空，模板展开时用系统默认热身建议补，不从视频硬猜。

### 4.2 组次与重量口径

- **口播有组次**：记 `target_sets / target_reps`，`lock_level=fixed`，并标来源为「口播」。
- **画面推测**：可填候选组次，标来源「画面推测」，审核时重点复核。
- **口播/画面都没有**：组次留空，**不按用户画像在模板层补重量**。
  - 重量属于单个用户，公开模板不存他人重量；具体重量由排课/打卡阶段按用户 1RM 计算。
  - 框架型模板可留组次区间槽位（如 3 组 8–12），但不锁重量。

### 4.3 动作匹配与库名反哺

- **匹配顺序**：别名表 → 中文名/英文名 → 部位 + 器械 + 动作模式语义匹配 → 视觉候选。返回候选列表与匹配置信度。
- **高置信**：自动挂 SKU；**低置信**：进待绑定池人工挑选；**库内无对应动作**：先以自由文本行保留（`exercise_id` 空、`exercise_name` 存口语名），标记待补录，不硬凑生僻译名。
- **审核反哺**：人工确认的正确口语名写入 `exercise_aliases`；若原 `name_zh` 译名不准，在动作精修台改名，旧名自动进别名表（沿用 A2 机制）。拆解过程同时完成动作库精修，不单建反哺表。

### 4.4 链接抓取降级策略

- 粘贴链接 → 后端尝试解析下载；成功则入库并在 `meta` 留存原链。
- 解析失败 / 被风控 / 无解析器：前端明确提示「请下载本地后上传」，走本地上传兜底，主流程不中断。
- 抓取逻辑封装为独立适配器，可整体关闭；不与加工管线耦合。

### 4.5 打分机制与审核分流

拆解/加工结果按四个维度分别打分，再汇总分流；**高分免检进草稿，低分强制人工审核**。

| 维度 | 打分依据 | 低风险信号 |
|---|---|---|
| 动作匹配置信度 | 别名命中 / 语义相似度 / 视觉候选一致性 | 无别名、部位器械不符、候选分散 |
| 片段证据完整度 | 是否有清晰可视片段、字幕是否提及该动作 | 画面模糊、动作一闪而过、字幕未提及 |
| 组次可信度 | 口播明确 / 画面推测 / 缺失 | 无组次、组次与画面组数不符 |
| 素材质量 | 时长、清晰度、动作幅度完整度 | 时长过短、抖动、未拍到完整幅度 |

分流规则（前端用状态色 + 文字双标识，不只靠颜色）：

- **绿（可入草稿）**：匹配置信度高 + 证据完整；可跳过逐条人工复核，发布前整体过一遍。
- **红（必审）**：任一维度低分、待绑定、自由文本行、组次为画面推测或缺失。
- 审核员工作台默认只列红/待绑定条目，绿条目折叠。

### 4.6 草稿状态

- 拆解生成的模板一律 `is_published=false`；素材一律 `status=draft`。
- 过完人工打分、绑定、补全后再发布；发布动作沿用现有模板上下架与素材 publish/rollback 机制。

### 4.7 GIF 产出

- 槽位 `role` 新增 `demo_gif`（或复用 `demo`，以 `meta.mime=gif` 区分；实现时二选一，见 §6.1）。
- GIF 取自高光切片 3～8s 循环段，FFmpeg 导出；需控制帧数、分辨率与配色体积，保证 H5 列表/详情加载。
- `highlight_video` 保留带声 MP4，不强制转 GIF。

## 6. 后端接口契约（挂载 `/api/admin`）

### 6.1 任务与入库

- `POST /api/admin/studio/ingest`
  - 入参：`file`（multipart，可选）或 `source_url`（可选）、`domain`、`product_kind`。
  - 行为：本地文件直接入库；链接先尝试解析，失败返回 `needs_manual_upload` 提示。
  - 出参：`task_id`、`status`。
- `GET /api/admin/studio/tasks`：任务队列列表，筛选 `product_kind / status / review_state / domain`。
- `GET /api/admin/studio/tasks/{task_id}/stream`：SSE 实时进度（转码/字幕/切片/打分）。
- `GET /api/admin/studio/tasks/{task_id}`：任务详情（字幕稿、抽帧候选、打分、产物引用）。

### 6.2 动作素材线

- `POST /api/admin/studio/exercise/confirm`
  - 入参：`task_id`、`exercise_id`、`role`（`start|end|demo|demo_gif|highlight_video|tip`）、`clip`（起止时间）、`export_format`（`mp4|gif|cover`）、`cues`、`mistakes`。
  - 落 `exercise_media(status=draft)`；发布/回滚沿用 `/media/{id}/publish|rollback`。

### 6.3 计划拆解线

- `POST /api/admin/studio/plan/parse`
  - 入参：`task_id`；触发分段与动作行抽取，返回草稿结构（板块、动作行、来源标记、置信度、待绑定清单）。
- `GET /api/admin/studio/plan/draft/{task_id}`：读取草稿与打分分流结果。
- `POST /api/admin/studio/plan/confirm`
  - 入参：草稿模板主信息、板块、动作行（含换绑后的 `exercise_id`、组次、角色、来源标记、片段引用）。
  - 落 `plan_templates(is_published=false)` + `plan_blocks` + `plan_exercises`。
  - 发布复用现有 `PUT /plans/{id}` 上下架。
- 待绑定条目复用 `/media-pool` 系列接口；拆解口语词绑别名复用 A5 的 `bind-alias` 思路（本期可先在动作行审核面板内联完成）。

### 6.4 服务拆分建议（`api/app/services/`）

```text
studio_pipeline.py   入库/转码/抽帧/字幕/高光定位/切片/GIF（共用，不含业务落库）
studio_score.py      四维打分与绿/红分流
studio_exercise.py   动作素材线：绑定 SKU 槽位、合并 Cues/Mistakes
studio_plan.py       计划拆解线：分段、动作行抽取、草稿生成、反哺别名
```
