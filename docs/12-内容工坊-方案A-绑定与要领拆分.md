## 1. 背景：为什么要拆

原工作台右栏一张动作卡同时承担 5 件事：

```
辨认是哪个动作 · 绑定 · 改动作名 · 比对要领 · 决定写不写库
```

无论怎么调整按钮顺序，卡片都会显得乱——问题不是顺序，是一件事都没减少。

**方案 A：按「草稿绑定」和「写总库」两层拆到两个界面。**

- 工作台卡片只回答一个问题：**这条口播对应库里的哪个动作？**
- 要领的逐条比对、替换/追加、写库，全部移到**点开该动作时右侧滑出的抽屉**里。

**图与文必须一致**：03 图卡片里不得出现要领区；要领相关控件只出现在 04 图的抽屉里。改图时不得往回加。

## 2. 拆分边界（不可再混）

### 2.1 工作台右栏 · 动作卡片（操作区）

只做「绑定」，不出现任何要领相关控件。

| 保留 | 说明 |
|---|---|
| 候选 top3 | 同名 / 别名 / 核心+器械，百分制分数 + reason 标签（同名、核心+器械、仅核心） |
| 点一条即绑定 | 选中态即生效，可再点换；**不设二次确认按钮**（去掉「就用这条 / 采纳」） |
| 搜库换名字 | 文字链，打开库内搜索 |
| 库里确实没有 → 新建 | 走 `quick_create`，新建时不带要领写入 |
| 状态灯 | 绿：≥90 且非含糊，可预填；黄：有候选未点稳；红：无候选，新建路径 |

| 移出卡片 | 去向 |
|---|---|
| 要领对比表、三态、写入按钮 | 右侧抽屉（见 2.2） |
| 改名对齐叫法 | 抽屉头部（属于改这条库记录，不再放卡片按钮条） |

卡片内不出现：覆盖 / 只补 / 不入库、要领文本列表、「写进这条动作」按钮。

### 2.2 右侧抽屉（动作详情）

承担「修改这条库记录」的所有操作。

**形态（定稿）**
- 从右侧滑出，宽 558px，占满内容区高度；**不新增路由、不换页**，工作台保持原样在底下。
- 抽屉外的区域压一层遮罩（约 58% 黑），工作台左栏（任务队列）和中栏（视频）仍可见但变暗。
- 右上角 `×` 关闭，回到工作台。关闭不保存任何未点的操作。
- 抽屉内自上而下：动作名 + 改名 → 要领（对比表 / 结论 / 三态 / 写入）→ 这段原话 → 历史要领。
- **注意**：不是独立页面，不要做成 `router.push` 那种跳转；路由最多用一个 query 参数标记当前打开的动作 ID。

**头部**
- 动作名 + `改名对齐叫法` 小描边按钮；改名时旧名自动写入别名表。

**要领逐条对比表**

| 库里现在（seed 导入） | 这次视频（带时间段） | 处理 |
|---|---|---|
| 保持肩胛稳定（删除线·灰） | 肩胛后收下沉，落点在乳线 | 换掉 |
| 控制下放速度（删除线·灰） | 下放三秒，推起一秒 | 换掉 |
| 库里没有 | 肘部过度外展，肩前侧代偿 | 新增 |

- 被替换的旧条目用删除线 + 灰色标注；新增条目琥珀色标签。
- 表下结论行：`前两条说的是一回事，视频版更具体；第三条库里没有 → 换 2 条、加 1 条，库里变 3 条`。

**三态（默认覆盖）**

| 选项 | 后果 |
|---|---|
| 按上面的换（默认） | 按配对表换掉重复项 + 追加新增项 |
| 只加不换 | 保留旧要领，只追加新增项 |
| 不入库 | 要领只留在本次视频草稿，不落库 |

**写入**
- 唯一按钮：`把要领写进库`（描边强调色，非实心主按钮）。
- 旁注：`不点就只留在这条视频的草稿里`。
- 不点写入，库内要领不变。

**这段原话（只读）**
- 抽屉下半列出该动作对应的字幕原句，带时间戳，作为判断依据。
- 只读，不可编辑；要点取自这里。

**历史要领（只读）**
- 抽屉底部折叠区，展示最近一次被覆盖的旧文本 + 替换时间 + 来源任务。
- 只读，无按钮、无还原。

**示范素材**
- 中间视频选区 → `截成示范段`（MP4，静音循环，H5 与后台详情共用同一文件）。
- 封面取选区首帧，同批生成 JPG。
- 计划封面由人工自己上传，未设时显示占位。
- **不产 GIF**；`end` 帧字段保留但当前不做。
- 示范素材的操作仍在中栏选区条上，**不在抽屉里**（抽屉只管要领与改名）。

## 3. 生效边界（两层）

| 层 | 动作 | 生效时机 |
|---|---|---|
| 草稿 | 点候选绑定、搜库、新建、拖选区、改草稿要领 | 立刻生效，只影响本任务草稿 |
| 总库 · 抽屉 | 改名、要领写入 | 抽屉内显式点对应按钮才落库 |
| 总库 · 中栏 | 示范素材入库（截成示范段 / 封面取首帧） | 中栏选区条显式点才落库；**不在抽屉里** |
| 发布 | 整计划出工坊 | 全屏唯一实心主按钮 `发布`；发布前校验所有动作已绑 `exercise_id` |

**备份口径**：覆盖前旧要领留档备查；**不做「还原」入口**（用户明确：要改就是要改，不提供反悔按钮）。备份当前存草稿行 `cues_library_backup`，后续视需要挪到库侧留档（换任务/换机器不丢）。

### 3.1 灯色与门禁（写死，避免与「点选即绑」拧着）

- **点选候选 = 立刻绑定 = 该行立刻转绿**。不再出现「卧推已选了平板杠铃卧推但仍显示待确认」。
- 灯色只表达「能不能发布」，**不表达「要领写没写」**。要领没写也照样是绿，因为领要不阻塞发布。
- 绿的判定：`exercise_id` 非空 + 无其他硬缺失（如示范素材可选、组次按热身规则判）。
- 黄：有候选但未点选，或分数 55～89 未选定。
- 红：无候选，需走新建。
- **发布门禁**：所有动作必须有 `exercise_id`（黄/红 = 拦）。要领、示范素材、封面都不拦发布。
- 底部状态文案随之改：`3 个待绑定 · 1 个库外 / 修完才能发布`，绑定完当场减少，不需要刷新或二次确认。

## 4. 后端与数据要求

### 4.1 草稿行字段（与现网字段的对应关系）

现网草稿行已有 `cues` / `mistakes`（视频抽出、按段落存）。本次**不删不改名**，在其上补齐：

| 本方案字段 | 与现网关系 | 说明 |
|---|---|---|
| `exercise_id` | 已有 | 绑定的库动作；未绑为空 |
| `candidates` | 已有 | 候选列表 `[{id, name_zh, score, reason}]` |
| `match_score` | 已有 | 百分制 |
| `spoken_name` | 已有 | 口播原话名 |
| `cues_draft` | **新 = 现网 `cues` + `mistakes` 的统一视图** | 只做读取聚合，供配对接口输入；**不新建物理列、不与现网字段并存**。实现上由 `cues` / `mistakes` 拼出 `[{text, timestamp, source_segment, kind: cue|mistake|instruction}]` |
| `cue_mode` | 已有 | none / append / replace；**默认值改为 `replace`** |
| `cues_library_backup` | 已有 | 覆盖前旧要领留档 |
| `cue_pairs` | **新增** | 逐条配对结果（见 4.2），失败时为空，走人工兜底 |

> 一句话：**`cues_draft` 是视图不是列**。实现的人不要新开数据库字段，从现网 `cues` / `mistakes` 聚合即可。

### 4.2 要领配对（对比表的数据来源）

- 新增配对接口：输入「库内现有要领」+「草稿要领」，LLM 输出逐条配对：

```json
{
  "pairs": [
    {"library_cue": "保持肩胛稳定", "draft_cue": "肩胛后收下沉，落点在乳线", "relation": "replace", "reason": "同一要点，视频版更具体"},
    {"library_cue": null, "draft_cue": "肘部过度外展，肩前侧代偿", "relation": "add", "reason": "库里没有"}
  ],
  "summary": {"replace": 2, "add": 1, "result_total": 3}
}
```

- 输入只是几条短文本（几十 token 量级），不是整段视频；一次小调用，成本可接受。
- `relation` 取值：`replace`（换掉）/ `keep`（保留旧的）/ `add`（新增）。
- 语义合并（同一条内去重润色）**暂不做**；默认覆盖，追加次之。

**配对失败的人工兜底（必须实现，否则接口挂掉就卡死）**

| 情况 | 界面表现 | 用户能做 |
|---|---|---|
| 调用超时 / 报错 / JSON 不合法 | 对比表降级为两列平铺（左库里全部、右视频全部），处理列显示 `待判断` | 逐条点 `换成这条` / `保留` / `新增`，人工指定 relation |
| 返回条数与输入不匹配 | 同上降级，缺的条目默认 `add` | 同上 |
| 库内要领为空（首次沉淀） | 不调配对，整表视为 `add` | 直接写入 |

- 兜底时**不阻塞写入**：人工选完 relation 照样能点 `把要领写进库`。
- 兜底结果写回 `cue_pairs`，与自动结果同构，不改下游写库逻辑。
- 超时阈值给 8 秒；超时即降级，不让用户干等。

### 4.3 留档给谁看（避免成为死数据）

`cues_library_backup` 的用途定死两条，不做第三条：

1. **排查用**：视频版要领入库后发现质量问题，后台查这条动作的 `exercise_id` 能翻到被替换的旧文本，用于判断是"原来那版更好"还是"新版的锅"。
2. **抽屉底部折叠区**：在抽屉底部加一个默认折叠的 `历史要领（只读）`，展示最近一次被替换的旧文本 + 替换时间。只读，无按钮。

不做的：不做「还原」按钮、不做版本对比视图、不做多版本时间线。若一周内无人查看，视为可下线。

### 4.4 写库

- 按配对结果落 `cues_zh` / `common_mistakes_zh` / `instructions_zh`。
- 替换前把旧文本写入留档字段。
- 新建动作：`quick_create` 支持 `write_cues`，默认 false。

### 4.5 沿用 11 的部分

- 匹配模块 `exercise_match.py`、百分制打分、候选 reason。
- 灯色规则；热身 `role=warmup` 抽取与主项池排除；不填假组次。
- 组次照抽但不入库（`Exercise` 表无 sets/reps 列）。

## 5. 交互原则（给前端落地）

1. **一个操作只贴一个对象**：按钮/入口必须挨着它改的那条东西，不集中堆在卡片底部按钮条。
2. **全屏唯一实心主按钮**：发布；绑定、写入、改名等其余操作一律描边或文字链。
3. **配置就地出现**：Cookie 进新建任务弹窗；模型与存储走服务端 env；不建集中设置页。
4. 对比表、三态、写入按钮同属「要领」这一组，必须在同一区块内出现，不拆散到卡片别处。

---

## 6. 明确不做

- 向量检索 / pgvector / 余弦相似度（现阶段先候选 top3 + 打分 + 人工确认）。
- 要领语义合并 merge；自动润色去重。
- 「还原库内要领」入口。
- GIF 生成与产物；`end` 帧当前不做。
- AI 生成计划封面（耗钱且不贴切）。
- 改名级联更新历史计划行（优先加别名）。

---

## 7. 验收标准

1. 工作台动作卡片里看不到要领文本、对比表、三态、写入按钮。
2. 点候选圈即绑定，再点可换；卡片上无「就用这条 / 采纳」类二次确认。
3. **点选候选后该行立刻转绿，底部待确认数量当场减少**；不出现「已选但仍待确认」。
4. 点开抽屉才看到逐条对比表；不点 `把要领写进库`，库内要领不变。
5. 默认 `replace`；对比表每条带处理标签，结论行有换/加数字与结果条数。
6. **配对接口失败/超时（>8s）时降级为两列平铺 + 处理列「待判断」**，可人工逐条指定 relation 并照常写入，不卡死。
7. 覆盖前旧要领写进 `cues_library_backup`，抽屉底部有只读 `历史要领` 折叠区；界面上不出现还原按钮。
8. 示范产物只有 MP4 示范段 + 首帧 JPG；无 GIF；计划封面为手动上传占位。
9. 未绑 `exercise_id` 的动作不能发布；要领未写、素材缺、封面未设都不拦发布。
10. 热身行无默认 3×8-12；纯 warmup 不进主项配课池。

## 8. 落地顺序建议

1. 前端：把卡片内要领区块整体移除，只留绑定候选 + 搜库 + 新建。**先删不加**，删完先看一眼够不够用。
2. 前端：绑定点选后立即更新灯色与底部待确认计数（不等保存、不二次确认）。
3. 抽屉：从右侧滑出 558px 覆盖层，不新增路由。内含头部改名、配对表、三态、写入按钮、这段原话、只读历史要领。
4. 后端：`cues_draft` 由现网 `cues`/`mistakes` 聚合（不新建列）；新增配对接口 + 超时降级；写库按 relation 落库 + 留档；`cue_mode` 默认改 `replace`。
5. 清理：移除卡片内三态下拉、`restore-cues` 前端入口（后端可暂留）、GIF 相关产物与字段引用。
6. 自测：`cd Gym_coach/api && python -m pytest tests/test_exercise_match.py -q`，再丢一条卧推/深蹲字幕任务走一遍「绑定 → 转绿 → 开抽屉对比 → 写入 → 发布」。
